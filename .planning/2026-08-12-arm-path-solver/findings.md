# Findings

- 实机失败码 `check_mask=1`，属于工具中心 IK 预检失败。
- 失败约在工具中心 `(0,109,230)`；pitch=-30 deg 时 117 mm 工具水平偏移约 101.3 mm，腕部轴心接近底座轴线。
- 基础 IK 枚举多个径向/肘部分支但只返回单一候选，路径层无法对整条路径统一选择连续分支。
- 当前目标是先以生产参数在电脑端完整回放，再接入固件，减少烧录试错。
- `ArmCartesianAppendToolCenterSegment()` 当前逐采样点调用单解 IK 并立即写入轨迹缓存，是分支错误实际发生位置。
- 跨区路径按最多16段构造；适合逐段保存候选并做动态规划，段首继承上一段末端关节，可避免为1536点长期增加大候选缓存。
- 路径缓存已放入64KB CCM，现有运行时约25KB；候选工作区应采用函数内/普通SRAM的单段临时缓存或静态复用，不能给全部1536点永久扩成4倍。
- Keil Target只引用一份 `../APPLICATION/arm/arm_kinematics.c` 和 `arm_trajectory.c`，不存在同名源码误引用。
- 检查时现有 `arm_kinematics.o/Engineer.axf` 时间为17:09，新全候选源码为17:19；当前镜像尚不包含本轮新方案，最终必须在实现完成后生成一次新镜像。
- 主机回放准确复现旧失败：sample 567、工具中心约 `(0,109,230)`、IK status 5。
- 根因之一是理论q1=90deg的圆弧边界受float误差影响略大于90；软限位有0.2deg容差，但自动区域复查原先没有容差。现已统一使用 `ARM_LIMIT_TOLERANCE_DEG`。
- 修复容差后暴露精确原点方位奇异；生产分段预检会继承段首q1方向，回放器也改为在原点继承上一有效方向。
- 正向与返回路径均通过生产运动学回放：15段、736点，无IK/限位/ID1/120deg安全/连续性失败。
- 新实机截图显示预检已通过：737点、失败段255、check_mask 0、workspace 0；失败已从预检转移到运行前故障。
- 应用`fault=2`对应`ARM_FAULT_FEEDBACK_TIMEOUT`，不是IK或命令结果。
- `ArmTask()`在进入时保存now_ms，邮箱同步预检期间CAN ISR会更新更晚的last_feedback_tick；随后旧now_ms与新反馈时间做无符号减法会下溢并误报超时。
- DP原实现还会为每个当前候选重复计算上一点候选，已改为每采样点只计算一次，降低Cortex-M4同步预检耗时。
- 新截图实测`preflight_duration_ms=178`且三轴`dm_online=0`，证明同步预检超过100ms控制/反馈窗口，三轴同时失能不是单轴CAN故障。
- ArmTask与DMMotorControl同属一个1ms任务；同步预检期间控制发送停顿。修复为预检每点调用受1ms内部节流保护的DMMotorControl，持续发送预检前原位保持目标。
- 轨迹第0段起始时间改为预检完成后重新读取HAL tick，避免一开始就带入178ms已逝时间。
